# Iris

Iris 是一个运行在本机的飞书个人 AI 助理。它把飞书机器人、真实终端和本地 Agent 连接起来：每个会话都会自动启动一个 Agent，既可以服务开发者自己的工作流，也可以先接待通过飞书联系开发者的人。

## 主要能力

- 多机器人：一个服务接入多个飞书应用，分别设置机器人名称、默认 Agent 和目录；按机器人隔离会话，控制面板不再提供创建会话入口。
- Agent 自动选择：首次使用优先选择本机 Codex，其次选择 Claude Code；扫描到的内置 Agent 直接使用固定配置，也可以维护多个自定义 Agent。
- 联系人接待：他人私聊机器人后，自动创建“与某某的对话”群聊，并加入联系人、开发者和机器人。
- 会话复用：同一联系人后续私聊会继续进入已有群聊和 Agent 会话。
- 当前群上下文：Agent 可自动识别当前会话绑定的飞书群；回答问题缺少上下文时，会先读取最近 1～100 条群消息，无需用户提供群 ID。
- 艾特模式：联系人群聊和机器人直接加入的群聊默认需要 `@Iris` 才触发回复。
- 助理模式：默认关闭；仅开发者可以开启。开启后，群成员 `@开发者` 会触发 Agent，最终卡片以“我是某某的助理”标明身份。
- 开发者模式：只有配置的开发者可以开关；开启后显示目录、模型、推理等级、Agent 重启、终端快捷键和自定义快捷键。
- Agent 切换：开发者模式卡片展示本机已安装的 Codex、Claude Code 和全部自定义 Agent，并在确认旧 Agent 退出后完成切换。
- Agent 恢复：Iris 使用当前 Agent 的精确会话 ID 恢复 Codex、Claude Code 和 `aiden x codex` 会话；未取得会话 ID 时回退到启动命令。
- 工作目录：每个会话默认使用 `~/Iris_Workspace/会话名称`，并可从飞书卡片切换到额外配置的项目目录。
- 设置保护：首次使用必须在独立页面设置并确认密码；后续通过独立登录页验证，安全登录状态保留 30 天。
- 环境检测：可在设置页按需检查 Node.js、Headless 浏览器、数据目录、飞书连接和 Agent 环境；结果仅即时展示，不保存也不影响主流程。
- Web 终端：直接在真实终端中输入和粘贴图片，展示当前 Agent 与目录，并可打开对应飞书会话；不再提供独立输入框、通知开关和快捷命令区。

## 开发运行

环境要求：

- Go 1.25 或兼容版本
- macOS 或 Linux
- 可交互 Shell；优先使用系统配置的 `$SHELL`，并自动回退到 Bash、sh、zsh 或 Fish
- 已安装并登录所选 Agent，例如 Codex CLI 或 Claude Code

启动服务：

```sh
make run
make build
./iris
```

默认监听 `8080`。也可以指定端口或独立配置目录：

```sh
go run ./cmd --port 8082
go run ./cmd --config-dir /data/iris
IRIS_CONFIG_DIR=/data/iris go run ./cmd
```

查看或停止本机运行中的 Iris 服务：

```sh
iris status
iris stop
iris restart
```

一个 Iris 服务可以管理多个飞书机器人；`iris stop` 停止服务，`iris restart` 重启整个服务，不再提供端口选择或 `all`。开机自启默认开启，可在「全局设置 → 安全 → 开机自启」关闭。旧版若仍运行多个进程，命令只控制配置中的主服务，不会静默删除或关停其他实例的数据。

云端部署请在「全局设置 → 安全 → 控制面板访问地址」填写实际可访问的 HTTP/HTTPS 地址（配置文件字段 `dashboard_url`）。飞书卡片的「打开终端」将使用该地址，并定位到对应机器人和会话；Agent 结束事件仍通过本机回调，不走公网。修改后刷新卡片可更新旧链接；留空沿用本机访问地址。

Iris 每次启动成功后都会自动打开本机 Dashboard，包括 `iris restart` 和开机自启。无桌面环境可显式使用 `--no-open` 或 `IRIS_NO_OPEN=1` 禁止打开。首次使用先进入独立的密码设置页，完成密码确认后才能进入配置台；之后在设置页配置飞书应用、开发者 open_id、工作目录和自定义快捷键。

Iris 启动时会自动安装并维护 Codex `notify`、Claude Code `Stop` Hook，以及两者用于识别当前飞书群的 Skill，并将 Codex 的 `check_for_update_on_startup` 强制设为 `false`，其他用户配置保持不变。安装包也会在安装完成后执行同样的配置；如当时没有写入权限，首次启动会自动重试。可手动执行 `iris --install-agent-hooks` 重新安装。

## 飞书配置

在「添加机器人」中填写名称、默认 Agent 和目录后扫码创建。Iris 会打开独立的飞书登录窗口，自动创建应用、配置权限和长连接事件、提交发布，并自动测试消息与权限；不读取日常浏览器的登录资料。企业若要求审批，会明确提示尚未上线，不会把未完成的配置当作成功。也可接入已有应用，保存时自动验证凭证。

机器人名称可单独修改；飞书应用名称从应用读取。应用配置包括 App ID、Secret、开发者通知接收 ID。联系人助理流程需要机器人具备消息、群聊、卡片和用户基本信息权限，其中包括：

- 消息接收与发送
- 群聊创建与成员管理（包括 `im:chat.members:write_only`，用于删除会话时将机器人移出群聊）
- 卡片读取、写入和回调
- `contact:user.base:readonly`

扫码创建会一并配置 `contact:user.base:readonly` 和 `im:message.group_msg`。已有应用必须具备相应权限，并完成发布/审批后才能通过保存验证。

## 飞书使用方式

- 普通私聊：自动建立或复用联系人群聊，消息交给 Agent 处理。
- `开始 会话名`：创建开发会话，默认开启开发者模式并关闭艾特模式。
- 直接把机器人拉进群：自动创建绑定会话，默认开启艾特模式、关闭开发者模式。
- 在群里发送 `/t 问题` 或 `/topic 问题`：创建话题及独立 Agent 会话，继承群主会话当前的 Agent 和工作目录；开启艾特模式时仍需 @机器人。会话名为 `[话题] 群名 · 问题摘要`。只发送 `/t` 时使用“新话题”，收到首个问题后更新名称。
- 话题内直接继续提问，卡片、完成提示和操作均留在该话题；不同话题与群主会话分别运行，绑定在 Iris 重启后保留。首次提示 Agent 读取来源群背景，之后默认只读取当前话题历史，不自动继续历史任务。目录继承不等于文件隔离：同目录下的文件仍然共享。
- 接受其他机器人发送的消息，但 Iris 不自动 @机器人发送者，也不发送该任务的“任务已完成”提示；Agent 正文中主动编写的 @ 保留。
- 卡片“开发者模式”：仅配置的开发者可以切换，其他已显示按钮可由普通群成员使用。
- 卡片“助理模式”：仅开发者可以切换；无法取得开发者姓名时，回复卡片显示“我是他的助理”。

## 设置密码

设置页可修改密码。忘记密码时，在运行 Iris 的本机执行：

```sh
iris --reset-settings-password
```

配置台不允许跳过密码。登录凭证通过 HttpOnly Cookie 保留 30 天，Cookie 不保存明文密码；修改或重置密码后，旧登录凭证立即失效。

## 运行数据

默认端口 `8080` 的数据目录：

- `~/.iris/conf/config.local.json`
- `~/.iris/iris.db`
- `~/.iris/data/uploads/`
- `~/.iris/log/iris.log`

其他端口会自动隔离到 `~/.iris/instances/<端口>/`。例如 `iris -p 8081` 不会与 `iris -p 8080` 共用配置、数据库、上传文件、会话恢复数据或日志；`IRIS_HOME` 可修改实例目录的根路径。

单服务内新增机器人的数据位于当前服务数据目录下的 `bots/<机器人 ID>/`。原有机器人的数据库和上传文件原地保留，不重编号。旧版多进程的数据不会被静默删除或自动混合。

迁移旧部署时仍可读取旧版环境变量，但新配置统一使用 `IRIS_HOME` 和 `IRIS_CONFIG_DIR`。

## 验证

```sh
make test
make test-browser
make test-codex-tui
make test-claude-hook
```

浏览器 E2E 会验证首次密码、Agent 初始化和真实终端链路；Codex TUI E2E 会验证 Iris 自动启动 Codex、单轮内容截取以及模型和推理菜单；Claude Hook E2E 会通过真实 Claude 回合验证 Stop Hook 的最终回复回调。
